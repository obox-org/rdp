# 补充规格：卡片列表搜索框 + 模糊搜索（v1.0.1）

| 项                       | 值                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 状态                     | 已实现（`manifest.json` / `package.json` = `1.0.1`）                                                               |
| 来源                     | 用户要求：「添加搜索框，包括 rdp，模糊搜索，并提交」                                                               |
| 变更类型                 | **对外行为变更**（界面新增一处交互）⇒ 走补充规格 + 单测；**不改**数据结构、扩展消息契约、打包形状与宿主 API        |
| 与既有 spec              | 增补 `docs/spec/rdp-remote-desktop.md` §5-B（卡片列表）与 design §3.9.1；**取代** spec §4 非目标里的"不做搜索"一条 |
| 参考实现                 | 另一个用户扩展 `extensions/webapp/src/search.js`（同款搜索：**同一套匹配语义 + 同一份 API 形状**）                 |
| 不与既有 spec 冲突的条款 | 非目标里的"不做连接分组/标签/导入导出"仍然有效（本次只加搜索）                                                     |

## 1. 需求

1. 卡片列表**上方**一个搜索输入框；**输入即实时过滤**（不需要回车/按钮）；
2. 无匹配时显示**空态**（复用扩展既有空态组件，不新造第二种空态样式）；
3. `Esc` 清空搜索框并**恢复全部**；
4. 模糊匹配（子序列即可命中）、大小写不敏感、多词 AND、空查询返回全部且**保序**。

## 2. 交互与落点

| 项                | 决定                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| 位置              | `main.app__content` 内、卡片网格**上方**一行（`.search`），只在"确实有连接"时出现                      |
| 控件              | 复用既有 `.input` 样式（`type="text"`，占位文案「搜索名称 / 地址 / 用户名」，`aria-label="搜索连接"`） |
| 过滤时机          | Vue `computed`：`visibleRows = filterAndRank(rows, searchQuery)`，**没有**手动计时/去抖（纯函数够快）  |
| 排序              | 由 `filterAndRank()` 负责：**分数降序、同分保持原序**；空查询 ⇒ 原样返回（保持"最新在前"）             |
| Esc               | 搜索框自己的 `@keydown.esc` 清空（**不装全局 keydown**，不触碰 R-D4"模态框只走按钮"的既有约定）        |
| 空态（无匹配）    | 复用 `EmptyState.vue`（同图标同排版），文案换成「没有匹配的连接」且**不给主按钮**（清空走 `Esc`）      |
| 计数徽标 / 状态栏 | **仍是总数**（本次不引入"筛选中"的计数语义，避免又一次行为变更）                                       |
| 数据              | 纯前端过滤：不发扩展消息、不新增数据库列、不影响保存 / 打开 / 删除路径                                 |

## 3. 匹配语义（`src/search.js`，可测）

与 `extensions/webapp/src/search.js` 逐条一致（导出 `scoreTerm` / `isWordStart` / `scoreEntry` /
`parseQuery` / `filterAndRank` / `isSearching`；常量与加权档位也一样）：

1. **大小写不敏感**：查询与候选都先小写化（保留原串用于判定"词首"边界）；
2. **按字段分别打分取最优**：一个词在一条连接的所有可搜字段里取最高分，再把各词的分累加；
3. **子序列匹配**：查询字符按顺序出现即算命中（`chzi` 命中 `chenzhi`）；
4. **加权档位**：前缀命中 `1600` > 词首命中（分隔符或驼峰边界）`1300` > 连续片段 `1000` > 离散子序列 `600`，
   再加 `每字符 10` 与"命中密度"（`词长/字段长 × 100`；子序列按 `词长/跨度 × 200` 并与串首加成 `120`）；
5. **多词 AND**：查询按空白拆词，**每个词都要在同一个条目里命中**（词可以落在不同字段上）；
6. **空查询 / 纯空白** → 返回**全部**且**不改顺序**（返回副本，界面改动不污染原列表）；
7. 同分**保原序**：显式比较原索引（不依赖 `Array.prototype.sort` 的稳定性假设）。

## 4. 搜哪些字段（按 rdp 的**真实**字段）

rdp 的条目没有 webapp 的 `url` / `desc`，库行是 `.rdp` 字段表的扁平列（README §5）。参与搜索的是：

| 字段       | 来源                       | 说明                                                                   |
| ---------- | -------------------------- | ---------------------------------------------------------------------- |
| `name`     | 库列 `name`                | 连接名（卡片副行）                                                     |
| `host`     | 库列 `host`                | 主机（IP / 主机名）                                                    |
| `port`     | 库列 `port`                | 端口（未填按界面口径 3389 呈现）                                       |
| `username` | 库列 `username`            | 用户名                                                                 |
| `domain`   | 库列 `domain`              | 域                                                                     |
| `title`    | **派生**（`titleOf(row)`） | 卡片标题 `[username@]host:port`；与卡片显示**同源**，`host` 为空时不给 |

- 派生 `title` 的目的：**照卡片上看到的文字搜也能命中**（如 `chenzhi@10` 这种跨字段连写）；
- `host` 为空的畸形条目**不参与**派生标题——否则 `titleOf({})` 会拼出 `:3389` 这种条目里并不存在的文本；
- 因而"密码、`.rdp` 生成值、`data/` 里的文件路径"等**都不参与**搜索（它们不在 `list` 返回的行里）。

## 5. 与既有 spec / design 的关系

- **增补**：spec §5-B 的卡片列表（R-B2）与 design §3.9.1 的布局——在网格上方多一行搜索框，
  空态在"一条都没有"之外多一种"搜索无匹配"（同一组件、不同文案）；
- **取代**：spec §4 非目标中的「不做连接分组/标签/**搜索**/导入导出（需求没提，要加先问）」里的**搜索**一项——
  用户本次明确要求，越界问题已由用户回答；其余非目标（分组 / 标签 / 导入导出）**不变**；
- **不冲突**：design §3.9.5 / R-D4 的"模态框关闭只走按钮、不响应 Esc"仍然成立——
  本规格的 `Esc` 只挂在搜索框自身（`@keydown.esc`），不装全局键盘监听；
- **不改变**：数据模型（仍是 `api.sqlite` 的扁平列）、消息契约（仍是 `list`/`save`/`remove`/`open`/`probe`/`password`）、
  打包白名单（`src/` 不进 `.oix`，搜索匹配器随界面一起编译进 `ui/`）。

## 6. 非目标

- 不做高亮命中片段、不做搜索历史 / 建议、不做正则或字段限定语法（`name:` 之类）；
- 不做后端搜索（`list` 已经是全量列表，几十条量级前端过滤足够）；
- 不引入拼音转换（只做"字符子序列"层面的模糊，拼音首字母能否命中取决于用户自己输入的子序列）；
- 不改计数徽标 / 状态栏文案，不加"共 N 条命中"这类新信息。

   中文与主机名 / IP:端口、多词 AND、空查询全部且保序、首尾空白、同分保原序、边界输入；**既有 118 条全绿**；
2. `npm run build` → `ui/` 产出（搜索逻辑随界面产物一起进包）；
3. `node scripts/pack.mjs` → `out/rdp-1.0.1.oix`，且包内**无** `data/`、无 `src/`、无 `node_modules/`；
4. `npx prettier --check .` exit 0；
5. 界面门禁不受影响：`styles.css` 仍**零色彩 / 零字体族字面量**、只引用白名单 token
   （新增的 `.search` 只有布局属性，输入框复用 `.input`），`test/stylesTokens.test.js`、
   `test/fallbackInputs.test.js`、`test/formAlign.test.js` 全绿（标签列固定宽、窄窗堆叠等约定未动）。
