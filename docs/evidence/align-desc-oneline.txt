「说明行恒为一行」的实测与修正记录（2026-10-11）
需求：说明文本**仍是一行、简短**（设计 §4.3 / R-D4）；用户原话「选项描述最多一行，尽量简短」。

================================================================================
一、改前：1280 宽窗口下**逐条实量**，哪些 desc 折行
================================================================================
量法：无头 Chrome 直开 `ui/index.html` 的副本（docs/evidence/align-shots/measure-page.html，
      注入"打开模态框/展开高级区 + 量坐标与行数"的脚本；扩展源码未改），对**每一条** desc
      取 `getBoundingClientRect().height / line-height` 得行数，并另用一个"不换行探针"量出
      该段文字的**单行渲染宽度**。
控件列宽（同一份 dump 实测）：常用区 **446px**、高级区 **420px**（差 13px = 高级区容器内边距）。

结果（`descLineCountDist = [1, 2]`，即确实存在折行）：

  字段    区      单行需要   控件列宽   超出    行数   说明原文
  密码    common  449.19px   446px     +3.19   2     只交本机凭据管理器（cmdkey），不写 .rdp、不入库；编辑时清空即删除已存密码。

**折行字段只有「密码」一条**（65 条里唯一；高级区 33 条全部一行）。
次宽的三条及其余量（留一档安全边界）：
  · 窗口模式单显 (advanced) 414.77px / 420px（余 5.23px）
  · 驱动器       (advanced) 414.09px / 420px（余 5.91px）
  · 会话管理「管理会话」(common) 356.53px / 446px（余 89px）

================================================================================
二、改短后的新文案（语义仍准，三条要点一个不少）
================================================================================
改前：只交本机凭据管理器（cmdkey），不写 .rdp、不入库；编辑时清空即删除已存密码。
改后：只交本机凭据管理器（cmdkey），不写 .rdp / 不入库，清空即删除。

语义对照（逐条）：
  · 「只交本机凭据管理器（cmdkey）」→ **保留**：密码只进本机凭据管理器；
  · 「不写 .rdp」                      → **保留**：不写进 .rdp 文件；
  · 「不入库」                         → **保留**：不进扩展的库（api.sqlite）；
  · 「编辑时清空即删除已存密码」        → 缩短为「清空即删除」：动作与后果不变
    （清空密码框 ⇒ 保存时删掉 conn:<id> 的已存凭据），去掉的是"编辑时""已存密码"这类可从上下文得知的限定语。
  · 分隔符「；」改为「，」（半角斜杠 + 全角顿号 → 统一用「/」与「，」），省下约 30px。

句长对照：40 字 → 25 字；单行渲染宽度 **449.19px → 364.44px**（余量 446−364.44 = **81.56px**）。

================================================================================
（同一套量法、同一份副本、同一 1280 窗口宽；结果文件 docs/evidence/align-shots/measure-{common,advanced}.txt）

  · measure-common.txt   `descLineCountDist = [1]`，`descWrapping = []`
     最宽三条：密码 364.44/446、管理会话 356.53/446、全屏启动 355.25/446
  · measure-advanced.txt `descLineCountDist = [1]`，`descWrapping = []`
     最宽三条：窗口模式单显 414.77/420、驱动器 414.09/420、色深 368.63/420
  ⇒ **65 条 desc 全部只有一行**（常用区 32 条 + 高级区 33 条）。

另用一份**独立**的对照页（docs/evidence/align-measure/desc-widths.html，只 import 一份
src/fields.js 的副本）把 65 条 desc 逐条量了"实测宽度 / 估算宽度 / 真实折行数"，
落成 docs/evidence/align-measure/desc-widths.txt：
  · 尾部结论：`折行（>1 行）的字段：（无）`
  · 实测最大值 = 414.77px（高级区 singleMonInWindowedMode），其控件列 420px
  · **估算/实测 比值范围 = 1.15 ~ 1.47** ⇒ 纯字符宽度估算在宿主字体栈上会高估 15%–47%，
    不能拿它当"是否折行"的判据（这正是门禁改用**真实排版**测量的原因）。

================================================================================
四、把「一行」做成门禁
================================================================================
位置：test/formAlign.test.js 的 **A1⑧**（"1280 宽窗口下没有任何 desc 折行"）。

实现方式（**真实排版**，不是字符估算）：
  · test/descLinesBrowser.mjs 里的 `extractWidthRules()` **按花括号配对**从 src/styles.css
    原样抽出影响控件列宽的基础规则（`*` 盒模型、`:root` 的 `--label-w`、`.overlay`、`.modal`、
    `.modal__body`、`.field*`、`.accordion__body`），并**跳过 @media 块**（否则窄窗口的
    `grid-template-columns: minmax(0,1fr)` 会被当成基础规则，量出的列宽永远是 600px）；
  · test/fixtures/desc-lines.html 用这些真实规则渲染一段**最小骨架**（overlay → modal →
    modal__body → field / accordion__body → field），让浏览器自己算出两个区的 `.field__control`
    实际宽度（实测 448 / 424px；真实页面因为竖向滚动条再少 2px ⇒ 446 / 420，门禁按 ±8px 容差比对）；
  · 把每条 desc 放进**同宽、同字体、同行高**的真实容器里量行数；
  · 断言 `wrapping == []`；并断言两个区的列宽与 CSS 算式吻合（±8px）、模态框宽度落在 640 附近、
    高级区列宽 < 常用区列宽（防止抽规则时把两区搞混）；
  · **自检**：再用 `?w=320` 把列宽强制压到 320px 复量一次，必须**报出折行**——否则说明量法失效，
    绿色不可信。这条自检让"全绿"本身带上抗"夹具坏掉"的证据。
  · 找不到浏览器时 `t.skip()`（本机装了 Chrome，实际是跑满的；跳过时会在测试输出里显式标注）。

为什么不用"字符数 + 列宽"的保守估算：见上，估算高估 15%–47%，65 条里会误报 11 条，
门禁一旦误报就会被人为放宽，反而失去拦截力。

变异自证（红 → 还原 → 绿）：docs/evidence/align-mutation-A1-gates.txt 的 **A1-10**
  · 变异：把「密码」desc 改回原长句（`src/fields.js` 里一处字面替换，锚点恰好命中 1 次）
  · 结果：**A1⑧ 变红**（其余 A1 门禁不红，定位精确）
  · 还原：`src/fields.js` 与变异前逐字节相同，复跑**全绿**
  · 总判定：9+1 = 10 处变异全部被拦住且还原后全绿 ✔

范围声明：门禁只管 **1280** 这一档（`--label-w` 144 + 常用区/高级区两个列宽口径）；
**500px 等窄窗口降级下允许折行**（那时标签与控件已上下堆叠，说明行按单列宽度自然换行）。
